Launch-readiness audit (2026-06-27). The app is feature-complete vs the PDF; remaining work splits by owner.

**🔴 #1 BLOCKER (found 2026-06-29): the prod API has NO database.** `DATABASE_URL` is set to an EMPTY string in the `calmcarry-api` Vercel production env (confirmed via `vercel env pull` — value length 0), and `NODE_ENV` is not `production` (so `prodSecretGaps()` never fires; the API silently runs in dev-fallback). With empty `DATABASE_URL` the API falls back to ephemeral better-sqlite3, the Postgres-only `Init` migration (`CREATE EXTENSION "uuid-ossp"`) fails, no schema is created, so EVERY auth/account/billing/entitlement call returns 500 (login/register both 500; `/health` still 200 because it's a trivial query). Net: no real accounts, logins, or premium work on prod. FIX (Glowco infra): provision a real Postgres (Neon), set `DATABASE_URL` + `NODE_ENV=production` on the API project, redeploy (migrationsRun will then build the schema; migrations DO compile into `dist/migrations`). Workaround shipped meanwhile: a preview-only comp login (`mason@theglowcompany.co` / `GlowOrb2026`) grants a LOCAL premium session, gated by `EXPO_PUBLIC_COMP_LOGIN` which only the preview web export sets — never a store build.
